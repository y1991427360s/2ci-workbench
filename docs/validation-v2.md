# 二次设计项目一致性检查 V2

## 规则

| ID | 名称 | 默认程度 |
|---|---|---|
| C001 | 同电缆编号存在不同有向起终点 | ERROR |
| C002 | 电缆起终点为空或相同 | ERROR |
| C003 | 电缆规格缺失 | WARNING |
| T001 | 外部接线端子缺少电缆编号 | ERROR |
| C004 | 清册电缆无端子引用 | WARNING |
| T002 | 端子引用不存在电缆 | ERROR |
| T003 | 端子与清册两端柜名不一致 | ERROR |
| T004 | 同柜、同端子排重复物理端子声明 | ERROR |
| T005 | 同柜回路号关联不同电缆/设备 | WARNING |
| D001 | 关键字段为空 | WARNING / ERROR |
| T006 | 无回路、电缆或有效连接的孤立端子 | WARNING |
| C005 | 电缆仅有单柜侧端子记录 | WARNING |
| D002 | 输入缺失、歧义、解析失败 | ERROR / WARNING |
| M001 | 柜名映射冲突、目标不存在及重复柜子坐标 | WARNING |
| P001 | 现有路径计算问题及结果时效 | INFO / WARNING |

D001 中缺少电缆清册编号或端子号为 ERROR；柜名、外部接线目标及端子排名缺失为 WARNING。T001 和 C002 单独处理对应必填字段，避免重复消息。未提供端子数据为 D002 WARNING；无法读取清册为 ERROR。回路号按柜隔离，分支回路可指向多根电缆，因此 T005 需要人工复核。重复清册行具有相同起终点时不触发 C001；同号不同有向起终点触发 ERROR。

## 架构和可追溯性

引擎接受统一字典快照，不依赖 Flask、文件系统或 JS。Rule 包含 rule_id、name、category、severity、description、check、evidence、suggestion；每条 check 返回实体、消息、证据及必要的程度覆盖。适配层负责将 XLSX/CSV/TXT 转换成统一字段并附带文件、行/声明位置、raw。输出问题包含要求的全部追溯字段及建议。

XLSX 使用活动工作表，复用现有表头定位、纵向合并单元格、型号列名及柜名规范化工具；项目检查不要求长度列，也不对清册补列或保存。TXT 复用现有解析器，仅增加可选 preserve_duplicates 参数用于保留重复声明，默认出图行为不变。TXT 中的对象位置为解析后块号和端子位置，原始完整文本仍附于证据；CSV 行号为逻辑记录位置（多行单元格不等于物理文本行）。

报告利用原有成组原子写入工具，失败时还原上一轮 JSON 和 Markdown；每个工程有独立报告目录。以输入内容哈希识别过期，包含端子、映射、参数及路径结果。重新检查覆盖上一轮固定名称报告，不保留历史版本。进程内沿用工程操作锁，跨多个 Gunicorn worker 的输入修改/检查互斥尚未统一。

## 本次架构修复

- 新克隆缺少模板 data 目录导致无法创建工程：补齐参数模板，并提供空工程初始化回退。
- 普通批量上传同名输入会静默覆盖：改为拒绝，与 ZIP 导入保持一致。
- 工程路径及报告/上传路径增加解析后的工程边界检查，拒绝越界链接目标。
- Windows 缺少 IANA 时区数据：补充 tzdata 依赖，供已有计算时间与检查时间使用。
- 复用已有 CSV 编码读取、TXT 解析和报告事务写入，规则不进入 route 或浏览器。

## 当前模型边界

1. `vendor/core/models.py` 是预留数据接口，现有计算和出图仍分别使用自己的字典/模型；本次统一检查快照，没有迁移生产存储。
2. 现有 TXT 不保存显式真实电缆号、芯号及远端端子，电缆编号由分组次序生成，编辑次序会改变编号。CSV 支持检查所需字段，但与出图 TXT 是两份独立输入。
3. 同一个工程原出图入口只有一个柜名；完整双侧检查需要 CSV 提供两柜记录。重复端子按本柜+排号+端子号判断，多接线 TXT 共用同一声明，不算重复端子。
4. 路径计算问题多数是字符串，缺少稳定 entity_id 和结构化电缆定位；P001 引用原结果证据，尚不能为每个旧路径问题准确反推出电缆号。无结果或过期时明确标记未验证路径。
5. 尚无电缆芯数、接线芯号、端子用途、备用状态统一字段，无法确定“孤立”是否为预留备用，也不能检查芯号一一对应。0 ERROR 不能代表所有未提供数据已经验证。
6. 身份认证是单工作台共享权限，工程隔离指文件边界和操作目标隔离，并非多用户访问权限。

## 下一阶段规则

优先在明确保存芯号及额定芯数后检查“芯号重复、超出芯数、两侧芯号/端子不对应”。随后可在路径计算输出结构化问题后检查电缆端点接入、跨层竖井及路径断点。先补齐这些必要字段，避免通过推断产生误报。

## 验证

`tests/test_validation.py` 内含正常快照、每条规则的最小变异 fixture、CSV/别名、空字段、TXT 重复及不存在端子引用、真实 API 上传/报告/过期/隔离、重复上传拒绝和报告事务回滚测试。`scripts/accept_validation.py` 将正常与故障工程实物及报告留存，便于重跑和工程复核。
